# AGENTS.md

Guidance for AI coding agents (and humans) working on this repository: a workshop on programming
eye-movement experiments with OpenSesame 4 and PyGaze, for researchers who have used neither.

## Layout

## Commands

```bash
python experiments/extract_comas.py                           # EyeTrack script -> comas.csv
/home/ubuntu/venv/bin/python experiments/make_vwp_stimuli.py  # redraw VWP pictures (keeps audio)
python experiments/build_osexp.py                             # regenerate .osexp (any Python 3)
/home/ubuntu/venv/bin/python experiments/test_headless.py     # all four, all trials (boundary ≈ 15 min)
/home/ubuntu/venv/bin/python experiments/test_headless.py --fake-eyelink --max-trials 3   # EyeLink-only items
/home/ubuntu/venv/bin/python experiments/check_interest_areas.py   # letter/word positions vs pixels (~10 min)
/home/ubuntu/venv/bin/python experiments/test_headless.py reading boundary --max-trials 4   # quick
/home/ubuntu/venv/bin/python experiments/test_headless.py vwp --screenshots /tmp/shots      # PNG per display
quarto render slides/workshop.qmd                             # slides -> slides/workshop.html (git-ignored)
```

- The test harness needs the OpenSesame venv (`/home/ubuntu/venv`) and an X display. The devcontainer
  runs Xvfb on `:0` (`.devcontainer/start-desktop.sh`); elsewhere use `xvfb-run -a`.
- `opensesamerun` is **broken** in this image (OpenSesame 4.1.17: its entry point
  `libqtopensesame.__main__.opensesamerun` does not exist). The harness runs experiments through
  `libopensesame.experiment.Experiment` instead.
- VWP audio needs Piper TTS (not in the image): `pip install piper-tts` in a separate venv,
  download the `en_US-ljspeech-high` voice from `rhasspy/piper-voices`, then
  `make_vwp_stimuli.py --piper <venv>/bin/piper --voice en_US-ljspeech-high.onnx`.
  Re-generating audio changes `target_onset` in `vwp_pool/stimuli.csv`; rebuild afterwards.
- The full workflow after any change to an experiment: edit `build_osexp.py` → run it → run the
  harness → commit the generator **and** the regenerated `.osexp` files together. CI does not exist;
  the harness is the test suite.

## How the harness works

`test_headless.py` monkey-patches the PyGaze advanced-dummy tracker (`pygaze._eyetracker.libdummytracker.Dummy`)
and the legacy keyboard backend:

- `sample()` returns a scripted gaze path that reacts to the experiment's own `eyetracker.log()`
  messages: `VALIDATION POINT` → on the dot; `GAZE TARGET ON` → on the target; `STIMONSET` → reading:
  fixations of 200 ms placed exactly on letter boundaries with ±0.3 letter of sinusoidal drift, and
  20 ms saccades of 7 letters, then the corner (`participant.fixations` records them); `AUDIO_ONSET` → competitor, then target, then a
  (patched) mouse click on the target.
- The trial counter advances on the status message `trial n/N item … condition` (logged by
  `start_recording`); keep that format.
- In trial 2 the participant ignores the first gaze target (10 s timeout → drift correction); in
  trial 3 the "experimenter" presses C (calibration + validation).
- Keys: `1`/`2` (80 % correct) when the keylist contains `1`, `space` otherwise, `None` for polls.
- `--fake-eyelink` replaces the line `EYELINK = items['pygaze_init'].var.tracker_type == 'EyeLink'`
  in the script with `EYELINK = True` and records `send_command` calls. Keep that line verbatim.
- If you add or rename a message, a variable, or a helper used by the harness (`GAZE_LEFT`,
  `GAZE_SIZE`, `letter_x`, `POS`, `objects`, `target_position`), update the harness too.

## Testing strategy

There is no eye tracker, no participant and no CI here, so every change is tested in layers that
can run in the container. "It runs without an error" is never enough: the experiments must produce
the right **data**, the displays must look right, and the slides must be readable.

### Principles

1. **Check against an independent ground truth, not against the code's own calculation.**
   Interest areas are compared with the *rendered pixels* (`check_interest_areas.py`), not with
   another `text_size()` call. The counterbalancing checks recompute the expected condition from
   the subject number and the item. Tracker messages are compared with the rows of the data file.
   Facts about papers come from Crossref or the manuscript, not from memory.
2. **Every new check must be shown to fail.** Run it once against a deliberately broken variant
   before trusting it. Examples: the moving-window lock removed → 756 window changes during
   fixations (FAIL); plain `text_size()` → boundaries up to 0.8 letter off (WRONG). To test a variant
   without touching the repository: take the script from `build_osexp.build_experiments()[name][0]`,
   change it in memory, write it as `script.opensesame` into a `.osexp` in a temporary folder, set
   `test_headless.OSEXP` to that folder and call `test_headless.run()` / `check()`.
3. **Test the data file, not just the absence of crashes.** Most bugs found so far ran without an
   error and only showed in the log: a global overwriting the `changed` column, `block_order`
   missing because it was created after the first `logger` call, `text_size()` boundaries, a font
   that silently fell back to another one.
4. **Look at it.** Automatic checks cannot judge whether text overlaps, is too small, or whether an
   animation makes sense. Save screenshots (`--screenshots`, `check_slides.py --out`) and look at
   them, including animation frames at several times.
5. **Keep the full output.** Save test output to a file instead of only filtering it with `grep`; an
   intermittent failure whose log was not kept cannot be diagnosed. Checks print the offending
   trials/messages in their detail text; keep it that way when you add checks.

### Layers

| What | Tool | When | Passes when |
|------|------|------|-------------|
| Experiment logic and data | `test_headless.py NAME --max-trials 4` | after every change to `build_osexp.py` or the materials | `ALL PASSED` |
| All counterbalancing versions | `test_headless.py` at full length (see matrix below) | before a commit that touches conditions, lists, blocks or loops | `ALL PASSED` for every subject number |
| EyeLink-only items | `test_headless.py --fake-eyelink --max-trials 3` | after changes to `eyelink_*` items, interest areas or messages | `ALL PASSED` (and without the flag: "EyeLink-only items do nothing") |
| Letter and word positions | `check_interest_areas.py` (default: all 488 sentences, legacy backend); also `--backend psycho`, `--font ... --font-file ...` | after changes to fonts, `TEXT_LAYOUT`, sentence position or materials | `RESULT: ... CORRECT` (≤ 1.5 px) |
| Displays | `test_headless.py NAME --max-trials 2 --screenshots DIR [--screenshot-trials ...]` | after changes to what is drawn | you have looked at the PNGs |
| Loads in the OpenSesame GUI | `DISPLAY=:0 opensesame experiments/osexp/NAME.osexp &`, screenshot of the noVNC desktop | after structural changes (new items, sequences, plugins) | the item tree appears, no error dialog |
| Slides | `quarto render slides/workshop.qmd`, then `slides/check_slides.py --out DIR --anim-times 2,6,12` | after every slide, CSS or animation change | `OK` (no OVERFLOW, INNER-SCROLL, DISTORTED, JS error) **and** you have looked at the screenshots |
| Container | rebuild the devcontainer | after changes to `.devcontainer/` | the commands above work with `/opt/slides-check/bin/python` |

Full-length matrix (each run prints `ALL PASSED`; boundary takes ≈ 15 min, runs can be started in
parallel on the same X display):

| Experiment | Subject numbers | Why |
|------------|-----------------|-----|
| `reading` | 1, 2 | both lists (parity); together every item in both conditions |
| `boundary` | 1, 2, 3 (ideally 1–6) | all three block orders (`subject_nr % 3`) × both preview lists |
| `movingwindow` | 1, 2 | both lists (window 4 / 12) |
| `vwp` | any | no counterbalancing; all 8 trials |

### What the harness checks

For every experiment: one data row per loop cycle; no aborted trials; validation before the first
trial (5 points, accepted, error logged in degrees); the status message and `TRIALINFO` match the
row; tracker messages in the right order per trial; no corner/boundary/click timeouts; recovery from
an ignored gaze target (trial 2) and from the experimenter's C key (trial 3); one `REGION` per word
or picture, touching word areas, one `LETTER` per letter; responses only after questions, scored
against the `answer` column. Per experiment: list and condition assignment (reading, moving window),
preview condition, block order, display change in every trial, latency logged, boundary between the
last pre-target letter and the first target letter (boundary); no window change during fixations and
the window on the last fixated letter (moving window); click on the target, RT from target onset,
`TARGET_ONSET` within 10 ms of audio onset + `target_onset` (visual world).

The simulated participant is deliberately imperfect where real participants are: it drifts across
letter boundaries during fixations, ignores one gaze target, gives 20 % wrong answers.

### What this cannot test (do it in the lab)

Anything that needs real hardware or real people: that an EyeLink accepts the Host PC commands and
writes the messages to the EDF; display-change and audio latencies on the lab PC and monitor (the
Xvfb numbers are meaningless); real tracker noise (tune `min_saccade_letters`, the 20 ms settling
time, `validation_threshold`); Windows font rendering (run `check_interest_areas.py` on the lab PC);
how the slides and animations look on the projector. `plan.md` lists these as pilot steps.

## Experiment conventions (keep these consistent across all four)

- Experiment: `pygaze_init` → `setup_helpers` → `eyelink_setup` → `validate_calibration` →
  `instructions` → (`counterbalance`) → loops → `goodbye`.
- Trial skeleton: `setup_condition` → `prepare_trial` → `drift_correct` → `eyelink_trial_start` →
  `start_recording` → `log_trial` → `show_gaze_target` → `trial_display` →
  `comprehension_question`/`keyboard_response` (run if `question != 'NA' and trial_aborted == 0`) →
  `clear_screen` → `logger` → `stop_recording` → `eyelink_trial_end`.
- Every `prepare_trial` sets `var.condition` (status line, Data Viewer) and the global
  `interest_areas` list `(label, left, top, right, bottom)` in screen pixels and, for sentences,
  `letter_x = letter_edges(sentence)`; `log_interest_areas()` writes `REGION` (words / pictures) and
  `LETTER` messages at stimulus onset. Word areas touch: the space after a word belongs to it
  (convention of `examples/EyeLogic_LITE.osexp`).
- **EyeLink-only code** (`send_command`, `!V …`, `TRIALID`, `TRIAL_RESULT`, `DISPLAY_COORDS`) lives
  only in the three `eyelink_*` items and `eyelink_draw_host()`, always behind `if EYELINK:`, and
  every such item says "EYELINK ONLY" in its description and comments. The status line uses the
  generic `status_msg` (shown on the Host PC; printed by other trackers).
- Experimenter keys: C during the gaze target = calibration + validation; Escape = pause.
  Calibration / drift correction require recording to be stopped first.
- Counterbalancing: reading = two lists by subject parity (`item_list` A = even subjects: odd items
  with commas); boundary preview by parity and block
  order by `subject_nr % 3` (`counterbalance` item + conditional `run` lines).
- Geometry comes from the published experiment: 50 px gaze target at x = 100–150, vertically
  centred; sentence starts at x = 125 (inside the target); trial ends after 100 ms in the
  bottom-right 10 % × 10 % corner (square drawn at 94 %).
- Inline scripts use **only** the tracker-independent `eyetracker` object (`sample`, `log`,
  `drift_correction`, `start/stop_recording`). No EyeLink-specific `send_command` calls in the
  shared experiments; tracker-specific extras belong in clearly marked optional items.
- Slow work (creating `Canvas` objects, rendering text) goes in the **prepare** phase; the run phase
  only calls `show()` and polls. The boundary loop must not `sleep`.
- **Text positions: never use `canvas.text_size()` directly for positions.** It returns the size of
  the *inked* pixels (trailing spaces and the empty pixels at the edges of the first/last letter are
  not counted; `center=True` also drops the left ones), and with `center=False` it wraps text wider
  than `width/2 - x`. Use `text_width()` / `letter_edges()` from `TEXT_LAYOUT` in `build_osexp.py`
  (measure with a trailing `'|'`, `center=False`, `max_width=W`; first letter at
  `SENTENCE_LEFT + QTextDocument().documentMargin()`). `experiments/check_interest_areas.py`
  verifies them against the rendered pixels for every sentence (must print CORRECT); run it after
  any change to the font, the layout code or the materials. Plain `text_size()` puts word ends up
  to 0.8 letter too far left; the anchored `'|' + text + '|'` method is within ~0.25 letter on the
  right but its estimated left edge is ~0.9 letter too far left. In the slides, present this as
  general advice (do not single out an experiment); for already collected data with
  `text_size()`-based boundaries (e.g. `examples/ella_experiment_A.osexp`), the positions have to be
  calculated by hand in the analysis.
- **Fonts in the file pool do not load in OpenSesame 4.1.17**: `_register_custom_font` finds
  `<font>.ttf` in the pool, but `_register_font` looks it up in `openexp.resources`, warns
  "Font … not found" and Qt silently falls back to another font (Courier New → Nimbus Mono PS on
  Linux). Installed fonts work. Always check which font Qt really uses (`check_interest_areas.py`
  prints it).
- Monospace font (`mono` = Droid Sans Mono, 24 px); the moving window assumes it (masked text must
  have the same width as the sentence).
- **Moving window: the window is locked during fixations.** It moves only after the gaze has moved
  `min_saccade_letters` (1.5) from where it was locked; it then follows the gaze (dead zone ½ letter)
  until the gaze has been still (within ½ × min shift) for 20 ms, and locks again. Never update the
  window on every sample: a fixation on a letter boundary makes it flicker. Do not replace this by a
  plain "ignore moves < 1.5 letters" rule: the in-flight samples of a saccade are small steps, and
  the window would stop short of the landing position. `test_headless.py` checks that there are no
  window changes during fixations (it fails with the protection removed: 756 changes).
- **Logger gotcha**: the CSV columns are fixed at the first `logger` call. Variables first created
  later (e.g. after practice) are silently never written. Create them before the first trial.
- **OpenSesame 4 gotcha**: inline-script globals *are* experimental variables
  (`python_workspace._globals is var.__vars__`). A global named like a loop column overwrites it and the
  wrong value is logged. Never reuse column names (`changed`, `target`, `sentence`, `item`, …)
  as helper names.
- Use OpenSesame 4 syntax in generated items: `{var}` in text, Python expressions in run-if.
- Coordinates: `Canvas` uses (0, 0) = screen centre; `eyetracker.sample()` uses (0, 0) = top-left.
- Escape (legacy backend) opens OpenSesame's pause screen inside `get_key`; `wait_for_fixation`
  returns `'escape'` after the experimenter resumes. During the gaze target this triggers a drift
  correction; during the stimulus it aborts the trial (`trial_aborted = 1`, no question).
- Tracker messages are part of the data format; document new ones on the "Messages" slide.

## Slides

- **Narrative**: the deck is built around three challenges. Challenge 1 (opening slides, Part 4):
  rebuild the comma study (Angele, Gutiérrez-Cordero, Perea & Marcet, 2023, QJEP;
  `reading.osexp`); its sentences are the examples **everywhere** in Parts 1–4 (animations, tables,
  figures). Challenge 2 (Part 5): Experiment 1 of Serrano-Carot & Angele (2026), JEMR 19(1), 6
  (`examples/ella_experiment_A.osexp` → `boundary.osexp`). Challenge 3 (Part 6): the moving window
  (review: Rayner, 2014, Visual Cognition; no published example here, demo with the EyeLogic
  sentences). Part 7 switches gears to the visual world; Part 8 is data, testing, EyeLink extras.
  New examples should come from these studies' materials, not invented sentences. Only state facts
  about the papers that are in their abstracts or the manuscript in `examples/frases-comas/`.
- Audience: researchers new to OpenSesame **and** eye tracking. Explain every term the first time it
  is used, prefer a screenshot or a table over prose, and keep code excerpts identical to the
  generator (copy, don't paraphrase).
- Screenshots in `slides/images/` come from `test_headless.py --screenshots` (1920 × 1080) or the GUI
  on the noVNC desktop. Regenerate them when the displays change.
- **16:9, 1920 × 1080, no scrolling.** `scrollable` is off on purpose: every slide must fit. Give
  sizes in px (the slide is scaled as a whole; `vh` follows the browser window, not the slide).
  Code blocks have no height cap; if code does not fit, split the slide.
- **Animations** (GSAP 3.12.5, vendored in `slides/js/gsap.min.js`, works offline): a slide contains
  `::: {.anim data-anim="NAME" style="height: 600px"}` and `slides/animations.js` draws NAME in SVG
  (or HTML for `structure`). Each `ANIMS.NAME(box)` returns `{tl, reset}`: a paused GSAP timeline and
  a function that undoes text changes made with `tl.call()`. Animations play when the slide is shown,
  loop, and restart on click. Use the shared helpers (`screen`, `gazeDot`, `monoLine`, `timer`,
  `caption`, `says`); keep text ≥ 22 px in the viewBox. Existing: fixations, loop, preparerun,
  structure, trial, waitfix, lists, boundary, blocks, movingwindow, windowlock, vwp.
- **Check after every change**: `quarto render slides/workshop.qmd`, then
  `/opt/slides-check/bin/python slides/check_slides.py --out /tmp/slides` (headless Chromium):
  Reports OVERFLOW, INNER-SCROLL, DISTORTED (displayed image aspect ratio differs from the file's)
  and JavaScript errors (must print OK) and saves screenshots of every
  slide and of each animation at `--anim-times`. Look at the screenshots: the check cannot judge
  readability or overlapping text. Mermaid's default style was unreadable on the projector; prefer
  an animation or an HTML/SVG diagram.

## Don'ts

- Don't hand-edit `.osexp` files or commit OpenSesame data (`subject-*.csv`, git-ignored).
- Don't modify anything under `examples/`. Fix errors in the source materials as documented
  corrections in the extraction script (see `CORRECTIONS` in `extract_comas.py`: item 19 had no
  comma in its comma version; restored after "deliciosa", as marked in the manuscript's word table;
  `corrected = 1` in `comas.csv`). The script asserts that every item's two versions differ only in
  punctuation.
- Don't commit rendered slides (`slides/workshop.html`, `slides/workshop_files/`).
